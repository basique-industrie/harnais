# Product, workflow, and visual review, 28 September 2026

This review followed the [code and performance review](code-review-2026-09-28.md). Three reviewers examined product priorities and navigation, workflow behavior and recovery, and visual hierarchy and interaction. The user confirmed equal priority for accounts, usage, connections, and skills. The resulting changes shorten access to those areas and protect edits while retaining Harnais's existing SwiftUI design.

The three reviewers examined the source; the root agent owns live app verification. Workflow coverage below means the entry points, actions, scope, and recovery paths were inspected. It does not mean every external login or destructive action was executed. Claims about likely user friction are design judgments, not measured task-completion results.

## Findings and decisions

| Review role | Observed issue | Decision |
| --- | --- | --- |
| Product | Global pages followed all provider account groups in the sidebar. Account detail could not directly open its connections or skills. | Give the four core pages stable placement above Accounts, retain every direct account entry, and add account-scoped library links. |
| Workflow | Page-local state reset when switching pages. A route labeled View limits did not explicitly select the Limits tab. Filtered shared connections hid connections unavailable to that account. | Own browsing state at the window level, make explicit routes select their intended view, and expose existing shared logins with an account-access action. |
| Visual and interaction | Generic Open labels obscured the destination. Library filters lacked a clear reset. Save actions could disappear when leaving an editing tab, and dismissal could lose edits. | Use explicit labels and existing compact controls, expose reset and keyboard actions, and keep save/recovery controls available outside the editor tab. |

The compact provider-grouped Overview was already present and is retained. This upgrade does not introduce another dashboard layout or merge Connections and Skills into a single catalog.

## Implemented in this upgrade

### Navigation and accounts

- Overview, Usage, Connections, and Skills appear above the independently scrollable account groups. Add account sits under the Accounts heading. Binaries and Settings remain in the footer. Existing shortcut assignments remain unchanged and appear in navigation hover help. See [ProviderSidebar.swift](../Sources/HarnaisCore/ProviderSidebar.swift).
- Window-owned navigation retains Usage tab, metric, range, breakdown and limit window; Connections search, account filter and Built-in expansion; and Skills search, account filter and section. Retention lasts while the window exists, not across app launches. Removing an account clears invalid filters even when their pages are hidden. See [HarnaisNavigation.swift](../Sources/HarnaisCore/HarnaisNavigation.swift) and [HarnaisRootView.swift](../Sources/HarnaisCore/HarnaisRootView.swift).
- Page shortcuts now use window focus, so they work without a focused text field. Commands cannot replace the underlying page while a sheet is open. The native View menu contains navigation instead of creating a duplicate View menu.
- View limits explicitly opens Limits with all windows visible. Ordinary navigation to Usage retains the user's last view.
- Account detail links to Connections and Skills with that account selected. These explicit routes clear an old search, and the Skills route opens its Skills section. They do not change account access. See [ProviderEditorView.swift](../Sources/HarnaisCore/ProviderEditorView.swift).
- Overview distinguishes Details from Open in Terminal. Installed, signed-in accounts can launch directly; accounts needing authentication retain Sign in. Actions have account-specific accessibility labels. Quota calculations, sorting, and attention thresholds are unchanged. See [AccountsOverviewView.swift](../Sources/HarnaisCore/AccountsOverviewView.swift).

### Finding and managing connections

- Connections and Skills offer Clear filters, Command-F to focus search, and Command-R to refresh. The existing responsive filter layout remains. See [HarnaisLibraryControls.swift](../Sources/HarnaisCore/HarnaisLibraryControls.swift).
- Shared connections remain discoverable under an account filter even when access is off. Status text explains that account's access; Manage access opens the shared connection's Accounts tab. Added and Built-in installations retain account filtering. Sync all still uses every shared connection's saved account selections; its help text states that filtering only changes the view. See [ConnectionsPageView.swift](../Sources/HarnaisCore/ConnectionsPageView.swift).
- Shared connection edits have a baseline snapshot. Done or Escape, opening app registration, and disconnecting prompt Save and sync, Discard changes, or Keep editing when needed. Interactive dismissal is blocked while dirty or saving. Clean reconnect starts authentication directly; dirty reconnect says Save and reconnect. Reconnect is secondary when already signed in. See [SharedConnectionSheet.swift](../Sources/HarnaisCore/SharedConnectionSheet.swift).
- Save and sync remains available without edits because it also repairs adapters. If settings persist but synchronization fails, the sheet stays open with the error and supports another sync attempt. It does not describe those persisted settings as unsaved.

### Skills and extensions

- Creating a shared skill opens its detail after the creation sheet closes, so the user can review it and choose accounts. Import folder continues to open the imported skill. See [NewSkillSheet.swift](../Sources/HarnaisCore/NewSkillSheet.swift) and [SkillsPageView.swift](../Sources/HarnaisCore/SkillsPageView.swift).
- Provider-extension management receives only the selected account's occurrences when filtered. This prevents its initial installation selection from pointing at another account.
- Unsaved shared instructions show a persistent footer status and Save instructions action with Command-S. Done and Escape offer Save, Discard, or Keep editing. Failed saves preserve the draft and reveal the Instructions tab. Interactive dismissal is blocked while dirty or busy. Existing guards against switching collection members with unsaved text remain. See [SkillDetailSheet.swift](../Sources/HarnaisCore/SkillDetailSheet.swift).
- Skill account installation changes still apply immediately. Discarding instruction edits does not undo already applied account changes; the dismissal prompt states this distinction.

## Preserved design and permissions

Changes reuse HarnaisPalette, typography, compact buttons, settings rows, segmented controls, Lucide and provider marks, and the 260-point sidebar. The existing page hierarchy, insets, and adaptive colors remain. Account identity and provider grouping remain visible. Keyboard navigation and per-account actions remain available; no command palette replaces them.

Navigation filters do not grant access, install skills, create logins, or narrow global Add/Sync operations. Shared, Added, and Built-in origins remain distinct. Provider-owned configuration, shared settings-file relationships, official auth flows, read-only restrictions, credential storage, T3 isolation, and destructive confirmation behavior remain in their existing domain and infrastructure implementations. No provider or service permissions were expanded by this UI work.

## Remaining recommendations

These are review proposals, not implemented changes:

- Extend Overview attention beyond low quota to actionable authentication, installation, and stale-data problems. Keep unavailable data distinct from exhausted capacity.
- Add a direct sign-in recovery action beside shared connections that need it. Current rows still route through Manage.
- Consider account-scoped Spend drill-down and links from usage rows to account detail. Current Usage remains global.
- Review connection creation's transition from authentication into explicit account selection and per-account results. Add clear in-place retry for failed account login. New skill creation already continues into detail in this upgrade.
- Consolidate Iles installation settings with Settings and consider clearer Iles tab naming. Keep ring selection near Limits and preserve an explicit route from Usage.
- Clarify availability discovery for shared skills not yet installed on the selected account. The current account filter shows installed shared skills; clearing filters exposes the broader library.
- Consider Back/history navigation, scroll restoration, and last-used views across launches after validating current window-level retention. None is claimed here.
- Review main-actor configuration writes and longer sync operations separately. This slice adds edit protection but does not make those operations asynchronous.

## Validation

- Debug and release builds succeed; all 784 regression checks pass. The final small filter-layout adjustment was checked through release packaging and live UI inspection.
- Packaged-app checks cover direct Overview actions, account detail links to Connections and Skills, account-filtered extension management, shared Accounts-tab entry, Clear filters, and retained Connections/Skills/Usage selections.
- Spend retained Tokens, seven days and Account breakdown after leaving and returning. View limits routing was inspected in source; no account was deliberately exhausted to trigger that action.
- Command-3 and Command-4 work repeatedly without text focus. Command-F focuses library search, and Command-R refreshes inventory. Page shortcuts do not dismiss an open shared-connection sheet. There is one View menu.
- Shared connection Done and Escape both showed Save and sync / Discard changes / Keep editing. Keep editing retained the draft; Discard left the saved Drive name unchanged. The account-scoped Manage access action opened Accounts with all seven existing toggles intact.
- A temporary shared skill was created without installing it in any account. Creation opened detail directly. Escape and Done protected its draft, Keep editing retained it, Command-S saved it, and a later Discard kept the earlier saved content. The fixture was archived under `/tmp` and removed from the registry after verification. All 171 existing skill occurrences still exactly match the pre-review snapshot.
- Filtering Provider extensions to Codex Personal produced an Installations view containing only Codex Personal. No extension was disabled or removed during this check.
- Overview and Skills were inspected at the 960-point minimum width using native window tiling. This exposed a wrapping Clear filters label; the filter controls now keep their width and let search adapt. Other pages and sheets were inspected at the existing larger window size. Exhaustive long-label, contrast and VoiceOver audits were not performed; the accessibility tree exposes individual Overview actions.
- Save failures were reviewed in source, not induced against real credentials or user skill sources. All currently shared connections are enabled for the registered accounts, so disabled discovery was verified in source without changing access. External login and destructive flows were not exercised during the redesign.
- The signed development bundle was packaged with `scripts/package.sh --dev`, gracefully quit, and relaunched from `dist/Harnais Dev.app`. The running process was verified after the final build.

The earlier code-review report records 84 successful live read-only checks across twelve shared connections and seven saved account configurations. The redesign changes presentation and routing; it does not repeat or broaden those external operations.
